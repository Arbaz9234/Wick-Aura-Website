Action Checklist

Grouped by priority. Check off items as you address them.

P0 — Critical Double-click / duplicate action risk
  • PlaceOrder "Place Order" button — add loading + disabled state No spinner, no disable. User can click multiple times and place duplicate orders. Add a loading state with spinner, disable the button during API call. PlaceOrder.jsx → handleSubmit + button
  • Account address "Delete" confirm button — add loading + disabled The confirm dialog's "Delete" button has no loading state. User can double-click. Add spinner + disable during confirmDelete(). Account.jsx → confirmDelete + delete dialog button
P1 — Important False empty-state flash (misleading UI)
  • Products loading — blank grid on Home, Collection, Wishlist products = [] on mount → LatestCollection, BestSeller, Collection all render empty grids. Add a loading state to ShopContext for products, show skeleton / spinner in consuming components. ShopContext.jsx → getProductsData + Home, Collection, Product pages
  • Cart loading — "Your cart is empty" flash cartItems = {} initially → Cart.jsx instantly shows empty state. Add a cartLoading flag, show spinner or skeleton instead of empty state while loading. ShopContext.jsx → getUserCart + Cart.jsx
  • Orders loading — "No orders yet" flash orders = [] initially → Orders page and Account Orders tab show "No orders yet" for 1-3s. Add loading state, show spinner while fetching. ShopContext.jsx → getUserOrders + Orders.jsx + Account.jsx
  • Addresses loading — "No saved addresses" flash + PlaceOrder form flash addresses = [] initially → Account shows "No saved addresses yet", PlaceOrder shows new-address form instead of saved addresses. Add loading state. ShopContext.jsx → fetchAddresses + Account.jsx + PlaceOrder.jsx
  • Wishlist loading — "Your wishlist is empty" flash wishlist = [] initially → Wishlist.jsx shows empty state before real data arrives. ShopContext.jsx → fetchWishlist + Wishlist.jsx
  • Profile loading — blank name/email inputs Account profile tab shows empty name + email strings for 1-3s while getProfile() runs. Show a skeleton or loading indicator on the profile section. Account.jsx → getProfile
P2 — Moderate Silent failures — user gets no feedback
  • getProductsData fails silently If product list API fails, console.error only. Products stay empty, entire site looks broken. Add toast.error or a retry mechanism. ShopContext.jsx → getProductsData catch block
  • getUserOrders fails silently console.log only on error. User sees "No orders yet" even if they have orders. Add toast.error. ShopContext.jsx → getUserOrders catch block
  • fetchAddresses fails silently console.log only. Addresses never load, user sees "No saved addresses." Add toast.error. ShopContext.jsx → fetchAddresses catch block
  • fetchWishlist fails silently console.log only. Wishlist shows empty. Add toast.error. ShopContext.jsx → fetchWishlist catch block
  • getProfile fails silently console.log only. Profile stays blank with no way for user to know it failed. Account.jsx → getProfile catch block
  • addToCart does not revert on fail Optimistic update adds item locally but does not revert if API fails (unlike wishlist which does revert). Toast shows, but cart state is inconsistent with server until refresh. ShopContext.jsx → addToCart catch block

  • Review submit — "Submitting..." + disabled + toast Product.jsx
